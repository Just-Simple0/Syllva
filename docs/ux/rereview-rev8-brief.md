# UX rev8 — 실패 회복 계약 집중 재리뷰

다음 버전 설계 정의의 최종 수용을 독립 검토해 주세요. 제품 구현·배포 검토가 아닙니다.
첨부의 UX-C1이 개정 후보이고 frozen 문서는 현행 기준입니다. 현재 코드가 새 포트를 아직
구현하지 않았다는 사실, 합성 모형이 모든 backend 상황을 재현하지 않는다는 사실은 결함이 아닙니다.
사용자가 Pro 사용량 제한을 밝혀 승인한 웹 ‘매우 높음’ 검토입니다.

이번 변경은 아래 3개 경로와 관련 표현뿐입니다. 나머지 실행 의미와 HTML 모형은 rev7과 동일합니다.
변경과 그 직접 영향의 구체적인 모순·불변식 위반·실행 경로 차단을 우선 검토해 주세요.

1. **UX-C1 §3.4, A38-folder:** 폴더 create payload에 `appProperties.uls_folder_key`를 포함합니다.
   부모/예약/source/entity/role에 결속된 hash와 create 시도 기록을 durable하게 저장하며,
   같은 OAuth 앱/계정에서 marker 전체 조회 후 0/1/복수 분기와 exact readback으로 회복합니다.
   raw뿐 아니라 새 중간 폴더도 동일하게 적용하며 부모 확정 후 자식을 진행합니다.
   응답 유실 후 검색 부재를 ‘create 안 됨’으로 단정해 재생성하지 않습니다.
2. **§6.5, A45-a/b/c:** FAILED/CANCELLED는 과거 request/attempt의 terminal 이력입니다.
   같은 note_key의 새 독립 active 요청은 새 attempt 또는 검증된 artifact를 사용할 수 있습니다.
   유효한 다른 request가 있는 shared job을 한 요청의 취소로 끝내지 않습니다.
   서로 다른 key의 늦은 완료, 같은 key의 동시 참조 취소, 취소 뒤 재요청을 별도 수용 사례로 둡니다.
3. **file-intake §4.2:** 날짜는 후보를 좁히는 용도이며, 정확한 수업 페이지/ID·USER 제목/별칭으로
   선택합니다. 같은 날짜 복수 후보는 자동 확정하지 않습니다. 실제로 없는 오전/오후 필드 문구를
   제거하고 전사 연결/자료 사용 상태도 별도 행으로 구분했습니다.

Drive 기능의 공식 근거는 UX-C1 §10에 직접 링크했습니다. 앱/계정 권한·provider 응답 유실·
SQLite crash/restart 등은 계약을 구현한 뒤 실제 시험 환경에서 검증합니다. 새 공급자·공개 공유·
운영 migration은 이번 요청에 포함하지 않습니다. 검색 MCP는 read-only이고 사람 승인/USER/Partial
불변식은 유지합니다.

HTML은 원격 호출 없는 합성 모형입니다. **34개 로컬 Playwright 검사**와 화면 확인은 유효하지만
실제 A01–A45 및 하위 사례의 backend 구현 완료가 아닙니다. HTML에 no-op provider 재현을 추가해
테스트가 된 것처럼 보이게 하지 않습니다. exact response-loss/shared-job 실행은 향후 수용 시험입니다.
모형의 demo-proposal ID는 암호학적 v2 ID 검증을 주장하지 않습니다.

한국어로 GO 또는 REVISE와 이유를 주세요. **판정마다 파일/라인/코드조각을 인용하라.**
필수 결함은 구체적 입력 → 잘못된 결과 → 최소 수정 → 수용 사례로 작성하고, 선택 개선과
실제 구현 후 검증을 분리해 주세요. 필수 결함이 없다면 남는 것이 구현 수용 시험임을 명시하세요.

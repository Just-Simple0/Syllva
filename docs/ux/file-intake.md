# 학습 대시보드와 파일 입력 UX 정의안

작성일: 2026-09-12
개정: rev10 + native 대시보드 적용, 2026-09-13. 사용자 표시 순서와 최대 3개 학습 바로가기 반영.

상태: **설계 수용 완료 — native 대시보드 적용, 새 자동 접수·생성 흐름 구현 전**. Notion의 ‘학기 대시보드 → 과목 → 세션’
접근과 Drive의 학기별 단일 업로드함을 기본으로 삼는다. 자동 정리가 어려울 때 과목별
폴더 템플릿으로 입력할 수 있게 한다. 아래 화면 구성·자동 분류 정책은 설계 제안이며,
실제 폴더 이동을 수행한 문서는 아니다. 대시보드·연결 뷰·파일 확인 화면의 직접 적용 범위는
[native 적용 기록](dashboard-native-application.md)에 구분한다. [UX-C1 실행 계약](intake-execution-contract.md)이
입력·저장·처리·권한·재시도 규칙과 다음 버전 명세 변경을 정의한다. 현행 frozen 문서는 보존한다.

## 1. 사용자에게 설명할 한 문장

> 학기 Drive 폴더의 ‘+ 업로드’에 원본 파일을 넣으세요. 시스템이 분류하고 필요한 정보만
> 확인한 뒤 정리합니다. 공부할 때는 Notion의 학기 대시보드에서 과목과 수업으로 들어갑니다.

사용자가 반복해서 할 일은 파일 추가와 필요한 확인이다. 내부 ID 생성, SOURCE/AI/USER
저장 영역 구성, 원문 해시, 정규화 파일 이름, DB 관계 편집을 일상 작업으로 요구하지 않는다.

이번 실제 수업 페이지에서 보완한 학습 노트 수준을 결과물의 기준으로 삼는다.
자료를 읽었다는 상태와 설명·예제·증명·문제·해설을 갖춘 학습 노트가 준비됐다는 상태는 다르다.

## 2. 사용자가 보는 장소와 역할

| 장소 | 사용자의 목적 |
| --- | --- |
| Notion 학기 대시보드 | 과목에 접근하고, 해야 할 일·과제 마감·시험·학사 일정을 한곳에서 본다 |
| Notion 과목 페이지 | 수업 목록, 과제·실습, 강의자료·교과서와 내 질문·필기를 본다 |
| Notion 수업·실습 페이지 | 연결된 자료와 학습 노트를 보고 공부한다 |
| Drive 학기별 ‘+ 업로드’ | 강의자료, 전사문, 교과서, 문제 파일과 내 풀이를 넣는다 |
| AI 대화 | 이해가 안 되는 부분을 질문하고 추가 설명·문제를 요청한다 |

기본안은 **Drive에 넣기 → 필요한 정보만 Notion에서 확인 → Notion에서 공부하기**다.
Notion의 ‘자료 추가’는 해당 Drive 업로드함으로 연결한다. 동일 파일을 Drive와 Notion에
각각 업로드하도록 요구하지 않는다.

### 2.1 Notion: 학기 대시보드 → 과목 → 세션

실제 사용 화면은 **Notion 내부**에 구성한다. 별도 HTML 앱이나 HTML 임베드를 도입하는
설계가 아니다. 대화에 제시한 HTML은 탐색·입력·상태 변화를 시험하는 합성 모형이며,
Notion에 이미 적용된 화면이나 Notion의 실제 외형을 그대로 재현한 것은 아니다.

공통 탐색은 **대시보드 · 현재 학기의 과목별 바로가기 · 파일 확인**만 둔다. 수업별 항목은
공통 메뉴나 별도 최상위 페이지 목록에 추가하지 않는다. 수업이 늘어도 메뉴 항목 수는
늘지 않는다. 과목 바로가기에서 해당 과목의 수업 목록을 열고 개별 수업으로 들어간다.
수업 안에서는 과목 수업 목록으로 돌아가는 링크를 제공한다. 대시보드의 ‘이어서 공부’는
수업을 최대 3개까지 여는 본문 바로가기이며 공통 메뉴 항목은 아니다. 현재 native 화면에는
확인된 수업 1개를 연결했다. 최근 열람 기록 수집과 자동 순위 갱신은 아직 연결하지 않았다.

Notion에서는 이 탐색을 **페이지 링크 묶음**으로 구성한다. ‘과목별 탭’은 과목 페이지로
가는 링크를 뜻하며, 별도 웹앱의 고정 메뉴바·맞춤 탭 동작을 그대로 요구하지 않는다.
수업 기록은 Sessions DB 페이지로 보관하고, 과목 페이지에는 해당 학기·과목으로 필터링한
연결된 목록을 둔다. 공통 탐색에는 현재 학기의 과목만 표시하며 좁은 화면에서는 링크가
여러 줄로 배치되어도 된다. 이전 학기는 해당 학기 대시보드에서 접근한다.

이 구성에서는 기존 Notion의 권한·편집·모바일 접근을 활용하는 편이 관리에 적합하다.
별도 HTML 앱은 화면 표현의 자유도를 늘리지만 호스팅·인증·상태 동기화의 관리 범위도
추가한다. 파일 정리와 AI 생성은 기존 설계대로 로컬 worker가 맡고, 사용자는 Notion에서
확인하고 공부한다. [탐색 결정과 검증 범위](navigation-notion.md)에 구현 대응을 정리한다.

```text
대학 학습
└─ 2026-1 · 학기 대시보드
   ├─ 해야 할 일 / 과제·시험 마감 / 학사 일정
   ├─ 알고리즘 1 · 과목
   │  ├─ 수업 목록
   │  │  └─ 2026-03-06 · 1차시 · 학습 페이지
   │  ├─ 과제·실습
   │  ├─ 강의자료·교과서
   │  └─ 내 질문·필기
   └─ 다른 과목
```

이는 사용자가 보는 접근 구조다. 대시보드와 과목에서 같은 과제·수업 기록을 필터링해
보여주며, 화면마다 별도 복사본을 만들지 않는다. 교과서나 여러 수업에 걸친 실습은 과목에
보관하고 필요한 세션에서 연결한다. 모든 파일을 한 세션 아래에 억지로 배치하지 않는다.

학기 대시보드의 표시 순서는 다음과 같다.

1. **내 과목:** 해당 학기의 과목 페이지에 접근한다.
2. **이어서 공부:** 학습 페이지 바로가기를 최대 3개 보여준다.
3. **To DO:** 내가 적은 할 일과 제출 과제 등 미완료 작업을 확인한다.
4. **캘린더:** 학사일정, 과제 마감일, 시험일정과 날짜 있는 개인 할 일을 함께 본다.
5. **파일 확인:** 자료 폴더와 사용자 확인이 필요한 항목에 접근한다.

현재 native 적용은 기존 학기 일정 DB를 To DO와 캘린더가 함께 읽는 방식이다. 기존 DB의
사용자 소유 상태·날짜를 편집하며, 데이터 이관이나 worker 연결은 수행하지 않았다.
아래 `내 일정과 할 일`은 향후 제품 실행 모델이다. 현재 설치와의 대응은 native 적용 기록을 따른다.

처리 로그가 대시보드의 중심을 차지하지 않게 한다. 학습 노트를 생성한 사실만으로
‘복습 완료’나 ‘과제 완료’를 기록하지 않는다. AI가 추천한 공부 항목은 추천으로 표시하고,
내가 정한 할 일과 구분한다. 마감일과 학사 일정은 입력값 또는 확인 가능한 공지에 근거한다.

개인 할 일과 새 학기 공통 일정은 단일 `내 일정과 할 일` 원본 DB에 두고 학기로 필터링한다.
과목은 선택 사항이며 완료는 내가 기록한다. 기존 학사 일정 DB는 별도 연결 뷰로 재사용하며
자동 이관하지 않는다. 과목 과제·시험은 Activities/Exams의 원본을 연결해 같은 기록을 보여준다.
첫 대시보드부터 이 영역을 포함한다. 학기 공통 일정을 특정 과목의 시험이나 실습으로 위장하지 않는다.
새 운영/개인 DB의 정확한 역할은 UX-C1 §2에 정의하며, 현재 설치된 DB로 취급하지 않는다.

### 2.2 Drive: 학기별 업로드함 하나, 정리는 시스템이 담당

아래는 첫 구현에서 사용할 보관 구조의 예다. 과목 코드는 초기 설정에서 실제 수강 과목으로
확정한다. Notion에는 ‘알고리즘 1’처럼 과목명과 자료 이름을 표시하고 원본 링크로 바로 연다.

```text
University/
└─ 2026-1/
   ├─ + 업로드/           ← 사용자는 여기에 파일을 넣는다
   ├─ COMP319-002/        ← 알고리즘 1의 시스템 관리 경로 예
   │  ├─ Recordings/S01/source/   ← 원본 전사
   │  ├─ Recordings/S01/derived/  ← 정규화·AI 결과
   │  ├─ Materials/M01/source/   ← 원본 강의자료
   │  └─ Materials/M01/derived/
   └─ 다른 과목 코드/
```

실제 보관 경로는 frozen 설계의 과목 코드·분반, 개체 ID, source/derived 구조에 맞춘다.
교과서는 Material의 유형이며, 표시상 따로 묶는다. 사용자는 내부 S01/M01 경로나 파생
파일명을 직접 관리하지 않는다. 같은 과목이라도 학기·분반이 다르면 별도 과목으로 연결한다.

단일 업로드함은 **정식 수집 이전의 접수 공간**이다. 여기서는 학기만 정해져 있으므로,
과목을 확정한 후 기존의 과목별 수집 경계로 전달한다. frozen 설계의 course-specific Inbox를
여러 과목이 섞인 Inbox로 그대로 바꾸는 것은 아니다. 접수 기록은 로컬에 지속 보관하고
Notion `파일 접수함`에 표시한다. 재시작 후에도 미정 파일과 입력 요청을 유지한다(UX-C1 §3).

파일을 넣은 뒤의 제안 흐름:

1. 파일을 접수하고 유형·과목 후보를 찾는다. 이미 등록된 원본의 identity나 사용자가 지정한
   과목 폴더 등 명확한 연결이 있으면 활용한다. 파일명이나 AI 추측만으로 과목을 확정하지 않는다.
2. 과목이 불분명하면 학기 대시보드의 **‘확인할 파일’**에 표시한다. 예를 들어 `Lec2.pdf`와
   `1주차.md`를 관련 입력 요청에서 함께 선택해 ‘알고리즘 1’을 지정한다. 선택한 파일에만 적용한다.
3. **‘입력 요청’ 페이지의 과목·자료 종류·날짜 등 필요한 속성을 채우고 ‘제출’을 체크**한다.
   일반 정보 제출이며 승인 절차가 아니다. 과목 지정과 같은 수업 연결은 각각 명시적으로 선택한다.
   수업에서의 실제 사용 범위 승인은 별도 완성된 제안을 통해 진행한다.
4. 정리할 대상이 확정되면 시스템이 과목 보관 경로로 옮기고, 이동 결과와 원본 링크를 남긴다.
   Drive 파일 ID를 유지하는 이동을 기본안으로 삼고, 복사 후 원본 삭제나 기존 파일 덮어쓰기를
   자동 정리의 기본 동작으로 사용하지 않는다. 실패한 파일은 접수 위치와 재시도 상태를 보여준다.
5. 연결된 수업·자료와 처리 결과를 Notion에서 확인한다. 분류 대기 중인 파일을 임의 과목의
   정식 Session/Material로 만들지 않는다. 학기 공통 공지는 별도 용도로 분류한다.

사용자가 파일을 넣는 일과 ‘어느 수업에서 몇 쪽을 사용했는가’를 확인하는 일을 분리한다.
과목만 정해진 PDF·교과서는 수업 날짜를 기다리지 않고 과목 자료로 등록할 수 있다.
입력 오류는 제출 결과에 원인과 새 입력 요청 링크를 표시하고, 단순 연결 실패는 같은 요청으로
재시도한다. 처리된 요청을 고쳐도 이미 정리된 원본을 다른 과목으로 자동 이동시키지 않는다.
요청 템플릿에는 ‘처리 후 수정하려면 새 입력 요청을 만드세요’를 안내한다.

### 2.3 선택 방식: 과목별 업로드 폴더 템플릿

자동 분류를 기다리기 싫거나 여러 과목의 모호한 파일을 자주 올리면 아래 방식을 선택한다.
첫 구현에서 자동 분류를 충분히 지원하지 못해도 같은 학습 화면으로 이어질 수 있다.

```text
2026-1/
└─ + 업로드/
   ├─ 알고리즘 1/
   └─ 다른 과목/
```

사용자가 과목 폴더만 고르면 과목 질문을 생략할 수 있다. 폴더 ID를 과목에 등록해 연결하며,
파일명이나 폴더 표시 이름의 변경만으로 과목을 다시 추측하지 않는다. 강의자료·전사문 등의
하위 폴더는 원하는 경우 제공하고 필수로 만들지 않는다. 이후 읽기·수업 연결·학습 흐름은
단일 업로드함과 동일하다. 완성된 내부 보관 디렉토리를 사용자가 직접 구성할 필요는 없다.

## 3. 학기 시작에 한 번 하는 일

학기 페이지를 만들고 ‘과목 추가’에서 과목명, 과목 코드, 분반을 정한다. 교수명은 있으면
추가한다. 학기 Drive 폴더를 연결해 ‘+ 업로드’와 정리할 위치를 지정한다. 기존 자료는 먼저
목록과 연결 상태를 확인하고, 이번 정의만으로 이동시키지 않는다.

선택적으로 과목별 업로드 폴더를 만들고 실제 폴더 ID를 과목에 연결한다. 그 폴더에 넣은
파일에는 과목 정보를 다시 묻지 않는다. 단일 업로드함의 모호한 파일은 접수 후 과목을 선택한다.

현재 테스트의 `COMP0319002` 폴더명은 COMP0319/002로 해석했고 PDF 표지에는
COMP319-002,003이 보인다. 운영 과목을 확정할 때 학교의 실제 과목 코드와 분반을
한 번 확인해야 한다. 이번 UX 정의 과정에서 기존 수업 ID를 바꾸거나 두 코드를 병합하지 않는다.

새 학기 초기 안내에는 다음 세 가지를 함께 보여준다.

1. ‘여기에 파일을 넣으세요’라는 학기 ‘+ 업로드’ 링크와 선택 가능한 과목 폴더 안내.
2. ‘여기서 공부를 시작하세요’라는 Notion 학기 대시보드 링크.
3. 자동 처리 PC가 오프라인이면 자료가 대기한다는 운영 상태.

학습 노트 자동 생성에는 처음 한 번 AI 공급자 연결이 필요하다. 연결 전에는 ‘AI 생성 연결 필요’를
보여주며, 사용자가 공급자·자료 전송 범위·비용 설정을 확인하기 전 새 서비스를 호출하지 않는다.
연결 후에는 Notion의 학습 요청으로 생성할 수 있게 한다. 공급자에 종속되지 않는 실행 계약은
UX-C1 §6에 정의한다.

초기 연결·권한 설정과 매번 파일을 넣는 동작은 구분한다. 정상 연결 후 매 파일마다
자격증명, 파일 ID 또는 설정 파일을 사용자가 직접 입력하게 만들지 않는다.

## 4. 파일 종류별로 무엇을 넣는가

아래 형식은 **목표 UX의 입력 기준**이다. 현재 자동 처리 지원 범위는 11절에 별도로 적었다.

| 종류 | 사용자가 넣을 것 | 필요한 정보 | 만들어질 연결 |
| --- | --- | --- | --- |
| 강의자료 | 교수에게 받은 PDF 원본. PPT/PPTX만 있다면 원본도 보관하고 변환 필요 여부 안내 | 과목은 접수 단계에서 결정. 자료 제목은 자동 제안, 해당 수업은 나중에 연결 가능 | 과목의 자료 1개 → 여러 수업에서 재사용 |
| 전사문 | 한 수업의 전체 UTF-8 `.md` 또는 `.txt`, 가능한 한 시간 표시 포함 | 실제 강의 날짜, 새 수업인지 기존 수업의 전사인지 | 수업 기록과 원문 시간 구간 |
| 교과서 | 원본 PDF 한 권 또는 이미 가지고 있는 장별 PDF | 책 제목·판본. 인쇄 쪽수와 PDF 페이지가 다르면 필요한 범위를 확인 | 과목의 보충 자료, 필요한 장·절·페이지만 선택 |
| 실습·과제 | 문제/공식 지침, 제공 코드·데이터, 내 풀이, 제공된 해설을 역할별로 구분 | 실습 이름, 자료 역할. 제출 과제라면 공지된 마감일 | 실습 기록 → 공식 지침 / 제공 자료 / 내 결과물 |
| 내 필기 | 필기한 PDF 또는 Goodnotes에서 내보낸 자료 | 어느 강의자료·수업의 필기인지 불명확할 때 확인 | 내 학습 기록으로 연결 |
| 시험·공지 | 시험 안내문·범위 공지 원본 | 시험명·일정. 범위는 근거와 함께 사람이 확인 | 시험 기록과 범위 제안 |

### 4.1 강의자료

- 다운로드한 이름 그대로 넣어도 된다. `Lec2-Algorithmic Analysis I.pdf`를
  `COMP0319-M01.pdf`로 바꿀 필요가 없다.
- ‘Lecture 2’는 자료의 이름이다. ‘두 번째 수업에서 사용했다’는 뜻으로 확정하지 않는다.
- 아직 어느 수업에서 쓸지 몰라도 미리 넣을 수 있다. 강의 날짜는 자료 등록의 필수값이 아니다.
- 하나의 PDF를 여러 수업에서 썼다면 파일을 복사하지 않고 각 수업에서 사용한 범위를 연결한다.
- 같은 수업에서 자료 여러 개를 썼다면 여러 자료를 연결한다.

### 4.2 전사문

- 현재의 Markdown을 유지하면 된다. TXT여도 동일한 UTF-8 본문이면 괜찮다.
- 권장 파일명은 `2026-03-06_전사.md`지만, 기존 `1주차.md`도 허용한다.
  파일명은 편의를 위한 힌트이며 실제 강의 날짜의 최종 근거로 자동 확정하지 않는다.
- 업로드한 날, 파일 수정일, 학기 첫째 주라는 표현을 실제 강의 날짜로 대신하지 않는다.
- `[0:01]`, `[15:35]`, `[1:05:13]` 같은 원래 시간 표시를 보존한다.
- 인식 오류를 직접 수정하거나 요약할 필요는 없다. 원문과 AI의 설명·용어 해석은 분리한다.
- 시간 표시가 없는 전사도 원문 보관은 가능하지만 정확한 시간별 이동은 제공할 수 없다고 안내한다.
- 녹음 파일만 올렸다고 전사까지 생긴다고 약속하지 않는다. 음성 전사 서비스 연결은 별도 기능이다.

사용자에게 보이는 추가 정보 입력 예:

```text
1주차.md · 알고리즘 1
종류: 전사문
강의 날짜: 2026-03-06
수업: 새 수업 / 기존 수업 선택
실제 차시: 새 수업일 때 선택 입력, 모르면 비움
입력 완료: 제출 체크
```

수업 연결 방식과 기존 수업은 처음에 비워 둔다. 날짜가 같아도 사용자가 정확한 수업을
선택하기 전에는 연결하지 않는다. 연결 예약 단계에서 멈췄다면 ‘새 요청으로 다시 선택 가능’인지
‘연결 결과 확인 필요’인지 구분해 안내한다(UX-C1 §4.3).

기존 수업을 선택하면 그 수업의 과목·날짜·차시를 확인하고 정확히 해당 수업에 연결한다.
새 수업을 추가하지 않으며 USER 필기·복습 상태를 보존한다. 다른 과목 수업이거나 다른 원본 전사가
이미 연결돼 있으면 자동 교체하지 않고 이유를 표시한다. 현행 할당기를 우회하는 대신,
UX-C1 §4의 검증된 기존 수업 연결 포트를 다음 버전에 추가한다.

새 수업의 내부 번호는 실제 차시와 다르다. 차시는 사용자가 입력한 값만 사용하고, 모르면
빈 상태로 등록한다. 날짜로 후보를 좁힌 뒤 정확한 수업 페이지/ID 또는 USER 제목·별칭으로
선택한다. 복수 후보가 있으면 자동 확정하지 않는다. 파일명이나 내부 번호를 ‘몇 강’으로 추측하지 않는다.

두 부분 시간 표시만 있는 전사도 유형 판별 후보로 인식해야 한다. 유형 추정의 근거가 약하면
‘자료 종류 확인’으로 보내며, 낮은 확신도의 기본 Material 분류를 그대로 정식 등록하지 않는다.

같은 날짜에 수업이 두 번 있었다면 날짜만으로 합치지 않는다. 정확한 기존 수업 페이지와
사용자가 정한 제목·별칭으로 구분해 선택한다. 첫 묶음에 오전/오후 입력 필드가 있는 것으로
가정하지 않는다. 한 수업이 여러 전사 파일로 나뉘었다면 수업과 파일 순서를 확인해야 한다.
**초기 입력 UX의 자동 처리는 한 수업·전사문 한 파일을 기준으로 한다.** 분할 전사
합치기는 아직 구현되지 않았으므로 임의로 이어 붙이거나 각각을 새 수업으로 확정하지 않고
‘분할 전사 확인 필요’로 안내한다. 원본을 잃지 않으며, 사용자가 원래 도구에서 단일 전사를
내보낼 수 있다면 그 파일을 사용한다.

### 4.3 교과서

- 수업마다 책 파일을 다시 넣지 않는다. 판본별로 한 번 등록하고 필요한 장·절을 연결한다.
- 수업 진도와 관련한 장·절을 알고 있으면 입력하고, 모르겠으면 나중에 지정한다.
- ‘PDF의 45번째 페이지’와 ‘책에 인쇄된 25쪽’을 구분한다. 확인되지 않은 쪽수 차이를
  모든 페이지에 적용하지 않으며, 인용은 확인된 PDF 위치로 돌아갈 수 있어야 한다.
- 스캔본, 그림·수식 중심 페이지, 암호가 걸린 파일, 처리 한도를 넘는 큰 파일은
  무엇을 읽지 못했는지와 다음 행동을 표시한다. 책 전체가 처리됐다고 보이지 않게 한다.
- 사용자가 처음부터 책을 임의로 잘라야 하는 규칙은 두지 않는다. 실제 처리 한도가 걸린
  경우에만 필요한 장 또는 처리 범위를 지정하도록 한다.
- 교과서를 넣었다는 이유만으로 모든 수업 노트나 답변에 포함시키지 않는다.
  첫 묶음에서는 ‘임시 자료 포함’ 요청에서 책을 직접 선택한다. 실제 확인/미확인 상태는 그대로
  표시하며, 함께 쓸 강의자료도 같은 목록에서 선택한다. 요청 문장만으로 자료를 자동 추가하지 않는다.

### 4.4 실습·과제

‘문제’와 ‘내가 쓴 답’을 구분할 수 있어야 한다. 같은 파일 형식만으로 역할을 결정하지 않는다.

```text
실습·과제/
└─ 실습 1 - 삽입 정렬/
   ├─ 문제와 제공자료/
   │  ├─ lab1.pdf
   │  ├─ starter.py
   │  └─ input.csv
   ├─ 내 풀이/
   │  └─ solution.py
   └─ 제공된 해설/
      └─ solution-note.pdf
```

위 구조는 정리 결과 또는 선택 가능한 업로드 템플릿의 예다. 직접 만들 필요는 없다.
단일 업로드함에 넣었고 역할이 불명확하면 Notion에서 관련 파일을 묶고 역할을 선택한다.
공식 지침과 교수 제공 파일은 공식 자료, 내 코드·보고서는 USER 결과물, AI가 만든 해설은
AI로 유지한다. ‘제공된 해설’도 교수 배포본인지 다른 출처인지 확인하고 출처를 구분한다.

제출하지 않는 연습 문제에는 마감일을 요구하지 않는다. GitHub 결과물은 파일을 다시
업로드하는 대신 저장소·경로와 정확한 commit/tag를 연결할 수 있도록 한다.
브랜치의 현재 내용이 과거 제출물이라고 추정하지 않는다. 파일을 받았다고 코드를 실행하거나
학교 시스템에 제출하는 동작은 포함하지 않는다.

## 5. ‘파일 등록’과 ‘수업에서 사용함’을 구분한다

파일이 같은 폴더에 있거나 파일 이름의 숫자가 같다는 이유만으로 수업 사용 관계를 확정하지 않는다.

알고리즘 1의 예:

```text
자료: Lec2-Algorithmic Analysis I.pdf
수업: 2026-03-06 · 1차시
전사: 1주차.md
```

시스템은 자료를 읽고 위 수업과 관련 있을 가능성을 제안할 수 있다. 실제 사용을 확정할 때는
대상 수업, 자료의 현재 버전, 확인 가능한 페이지 범위와 근거를 함께 보여준다.

```text
2026-03-06 수업에 이 자료를 연결할까요?
자료: Lec2-Algorithmic Analysis I.pdf
사용 범위: 미확인 / 지정 페이지 / 전체 자료
지정 페이지: PDF 시작·끝 페이지 입력
전체 자료: 이 수업에서 자료 전체를 사용한 경우에만 선택
다음 단계: 입력 제출 → 정확한 사용 제안 확인
```

처음 사용 관계를 만들 때는 그 수업의 **주자료 / 보조자료 / 참고자료** 중 역할도 선택한다.
기존 관계의 페이지를 바꾸는 요청은 정확한 사용 관계를 선택하고 기존 역할을 보존한다.
미확인·전체 자료로 바꿨다면 남아 있는 페이지 값을 비운 후 제출한다. 역할·수업·버전·범위를
포함한 제안 전체를 확인하며, 자료 종류만으로 사용 역할을 정하지 않는다(UX-C1 §5.2).

‘미확인’이나 빈 페이지 칸은 전체 자료를 사용했다는 뜻이 아니다. 미확인 상태에서는 전체 사용
승인 제안을 만들지 않는다. 지정 범위 또는 전체 사용을 명시하면 시스템이 최신 자료·수업·범위가
담긴 제안을 만들고, 사용자는 Notion의 해당 제안에서 승인/거절을 선택한다. **승인 선택 → 반영 대기
→ 적용됨**을 구분한다. 범위를 바꾸려면 새 입력으로 제안을 다시 만들며 과거 승인을 재사용하지 않는다.

확인 전에도 전사문 자체를 읽고 공부할 수 있다. 전사문만으로 학습 노트를 만들면 그 범위를
표시한다. 미확인 자료를 포함하려면 명시적으로 임시 자료 사용을 선택하고, 확인된 강의
근거와 구분한다. 수업 사용 확정과 시험 범위 확정은 별개이며, 하나로 다른 하나를 대신하지 않는다.

자료 연결 확인은 준비된 정확한 제안에 대한 사람의 선택이다. 단순히 ‘내용이 맞다’라는
대화나 노트를 열어본 사실로 `Verified`를 설정하지 않는다. 파일이 바뀌어 기존 확인 대상과
달라지면 과거 확인을 새 버전에 자동 적용하지 않는다.

## 6. 업로드 이후 사용자에게 보여줄 상태

하나의 ‘완료’ 표시로 모든 것을 표현하지 않는다.

| 구분 | 예시 표시 | 의미 |
| --- | --- | --- |
| 파일 접수·정리 | 접수됨 / 과목 확인 필요 / 정리 중 / 정리됨 / 이동 실패 | 어느 과목의 파일인지, 원본이 어디에 있는가 |
| 자료 읽기 | 대기 / 읽는 중 / 읽기 완료 / 일부만 읽음 / 읽기 실패 | 원본을 처리하고 검색 근거로 사용할 수 있는가 |
| 추가 확인 | 강의 날짜 필요 / 자료 역할 확인 / 새 버전인지 확인 | 사용자가 지금 결정할 것이 있는가 |
| 전사 연결 | 연결 안 됨 / 연결 예약됨 / 연결 반영됨 / 연결 확인 필요 | 전사가 정확한 수업에 연결됐는가 |
| 자료 사용 | 사용 범위 미확인 / 확인됨 / 새 확인 필요 | 해당 수업에서 PDF를 어떻게 사용했는가 |
| 학습 노트 | 아직 없음 / 요청됨 / 입력·연결 필요 / 만드는 중 / 재시도 대기 / 부분 노트 / 생성 실패 / 취소됨 / 준비됨 / 갱신 필요 | 요청한 근거로 설명·예제·문제·해설이 준비됐는가 |
| 내 공부 | 사용자가 기록한 복습 상태 | 실제로 이해하고 공부했는가 |

‘읽기 완료’는 원문의 내용이 모두 사실이라는 인증이나, 이미지까지 완벽하게 이해했다는
표시가 아니다. 추출하지 못한 페이지·수식·그림이 있으면 ‘일부만 읽음’으로 정확히 알린다.
정규화가 완료됐어도 학습 노트가 아직 없을 수 있다. 노트가 생겼다고 내 공부 상태를 바꾸지 않는다.
‘생성 실패’에는 실패 이유·마지막 성공 단계·원인 해결 후 새 요청 링크를 표시한다. 자동 재시도
중이면 다음 시각을 보여주고, 영구 오류나 재시도 소진을 계속 ‘만드는 중’으로 표시하지 않는다.
‘부분 노트’는 검증된 결과와 누락 범위를 함께 제공한다. 자세한 상태 대응은 UX-C1 §6.5다.

학기 대시보드의 ‘확인할 파일’은 여러 과목의 접수 문제를 모아 보여준다. 과목이 정해진
파일은 해당 과목에서도 같은 항목을 볼 수 있고, 어느 화면에서 해결하든 상태가 함께 갱신된다.

Notion 과목 페이지에 필요한 최소 영역:

1. **최근 수업·전체 세션:** 날짜·주제·학습 노트 상태와 학습 페이지 접근.
2. **과제·실습·시험:** 해당 과목의 마감, 내가 기록한 진행 상태와 상세 기록.
3. **자료함·내 질문·필기:** 강의자료·교과서·내 학습 기록과 원본 링크.
4. **자료 추가·확인할 항목:** 과목별 입력을 설정했다면 그 폴더, 아니면 학기 업로드함으로 이동.
   일반 Drive 링크로 들어갔다는 사실만으로 과목을 자동 전달했다고 간주하지 않는다.

세션 페이지는 날짜·주제, 연결된 전사·자료·사용 범위, 상세 학습 노트, 내 질문·필기·복습
기록으로 구성한다. 설명을 읽고 예제를 따라 한 뒤 문제를 풀 수 있는 학습 페이지를 목표로 한다.

화면 예시(구현 전):

```text
알고리즘 1
[자료 추가]

확인할 항목 1개
  1주차.md — 실제 강의 날짜 필요 · 입력 요청 페이지 열기

최근 자료
  Lec2-Algorithmic Analysis I.pdf — 읽기 완료 · 수업 연결 미확인

2026-03-06 · 1차시
  전사문: 읽기 완료
  강의자료: 사용 범위 미확인
  학습 노트: 아직 없음
  사용 범위: 범위 입력 요청 열기
  학습 요청: 새 요청 → 근거 ‘전사만’ → 제출 체크
```

파일 추가 후 기본 자동 동작은 접수·분류 제안과, 필요한 정보가 확정된 파일의 정리·정규화·
상태 갱신이다. **상세 학습 노트는 세션의 ‘학습 요청’ 뷰에서 새 요청을 제출하면 생성**한다.
기본 근거는 ‘전사만’이고 ‘확인된 강의자료 포함’ 또는 명시적으로 고른 ‘임시 자료 포함’을 선택할
수 있다. 요청한 자료가 없으면 입력 부족을 알리며 전사만으로 몰래 축소하지 않는다.
‘확인된 강의자료 포함’은 해당 수업에서 확인된 강의 슬라이드·교수 노트를 모두 대상으로 하며,
교과서·참고자료·강의계획서는 자동 포함하지 않는다. 선택한 근거를 일부만 읽었다면 부분 노트다.
매번 프롬프트를 새로 쓸 필요는 없다. 추가 질문은 선택 입력이다.
같은 수업에 요청을 여러 개 제출하면 가장 최근에 수신한 유효 요청을 현재 요청으로 표시한다.
이전 요청이 늦게 끝나도 최신 노트를 덮지 않고 이력으로 남긴다. 갱신 대기·실패 중에도 이전
노트는 근거 상태와 함께 유지한다. 각 요청의 취소·결과는 서로 구분한다(UX-C1 §6.2).

worker는 허용된 근거를 읽어 별도 생성·쓰기 경로로 AI 노트를 저장하고 Notion AI 영역에 반영한다.
생성 중·실패·준비 상태와 사용한 근거를 표시한다. 원본 버전뿐 아니라 사용 범위·관계·확인 상태가
바뀌어도 갱신 필요로 전환한다. 입력·저장·출력·재시도 계약은 UX-C1 §6에 고정한다.
노트 상단에는 근거 종류, 전체/부분 여부, 마지막 검증 시각을 표시한다.

학습 노트의 기본 수용 기준은 개념 설명, 단계별 예제, 필요한 증명·계산 과정,
오개념, 연습문제·해설, 원문 위치, AI 보충의 구분이다. 파일 접수 요약으로 대체하지 않는다.

## 7. 누락·중복·수정 시 사용자의 행동

| 상황 | 제안하는 동작 | 사용자에게 보일 다음 행동 |
| --- | --- | --- |
| 단일 업로드함에서 과목을 특정할 수 없음 | 접수 상태로 유지하고 과목 후보 제안 | 파일 하나 또는 선택한 여러 파일의 과목 지정 |
| 학교 전체 공지 등 과목이 없는 자료 | 임의 과목에 배정하지 않음 | 학기 공통 일정·공지 용도로 분류 |
| 실제 강의 날짜를 모름 | 임의 날짜로 새 수업 확정 금지 | 날짜 입력 또는 보류 |
| 같은 원본의 내용도 그대로 | 추가 처리·중복 생성 없음 | 기존 결과 열기 |
| 다른 파일 ID지만 내용이 동일 | 같은 과목의 중복 후보로 처리 | 기존 자료 확인, 다른 용도라면 구분 |
| 같은 파일의 내용이 변경됨 | 변경 이력을 남기고 파생 결과 갱신 | 새 버전과 영향받은 수업 확인 |
| 새 파일이 기존 자료의 수정본처럼 보임 | 파일명만으로 기존 자료에 덮어쓰기 금지 | 새 자료 / 기존 자료의 새 버전 선택 |
| PDF 일부를 읽지 못함 | 읽힌 범위와 누락 범위를 표시 | 원본 확인, 다른 PDF 제공 또는 처리 범위 선택 |
| 자료와 내 필기가 섞임 | 필기를 교수 원문으로 승격 금지 | 원본·필기 관계 확인 |
| 다른 과목 폴더에 잘못 넣음 | 정식 등록 전에는 새 입력으로 수정; 등록 후에는 자동 재배정 금지 | 등록 전 과목 입력 / 등록 후 ‘과목 연결 수정 필요·자동 수정 미지원’, 현재 연결 점검 |
| 파일 정리 중 이동 권한·연결 문제 | 원본 위치를 유지하고 완료 처리하지 않음 | 원래 파일 열기, 권한·연결 복구 후 재시도 |
| PC가 꺼져 있거나 연결에 실패함 | 접수 사실과 실제 처리 상태를 구분 | PC/연결 복구 후 재처리 |

미확인 문제를 묶어 보여주되, 정상 파일마다 승인 화면을 띄우지는 않는다. 파일을 다시
다운로드하거나 업로드하는 행동을 모든 오류의 기본 해결책으로 삼지 않는다.
자료를 교체해도 이전 원본 이력과 USER 필기를 잃지 않도록 한다.

Drive에 업로드됐어도 worker가 아직 보지 못한 파일은 Notion에 접수됐다고 표시할 수 없다.
대시보드는 최근 동기화 시각을 보여주고 오래됐으면 PC/연결 확인을 안내한다. 오프라인 동안
노트·근거의 최신성을 보장하지 않는다. 첫 버전 알림은 대시보드의 확인 항목과 상태 배지다.
파일 확인 아래에는 ‘업로드 후 다음 동기화 시 표시’를 안내한다. 재업로드를 기다림의 해결책으로
권하지 않는다. 새 범위 입력/제안과 기존 적용된 범위는 별도 상태다. 변경 제안을 거절하거나
새 초안을 미확인으로 제출해도 기존 유효한 사용 승인이 저절로 철회되지 않는다(UX-C1 §5.1).

## 8. 파일을 넣은 뒤 할 수 있는 요청의 예

- ‘3월 6일 알고리즘 수업을 예제와 증명까지 포함해서 공부할 수 있게 정리해줘.’
- ‘이번 강의에서 삽입 정렬의 유지 조건이 왜 성립하는지 다시 설명해줘.’
- ‘등록한 교과서의 관련 설명도 포함해서 설명해줘.’
- ‘실습 1 공식 지침을 먼저 확인하고, 내 풀이에서 막힌 부분을 도와줘.’
- ‘내 필기와 강의자료를 비교해서 내가 잘못 이해한 부분을 찾아줘.’

마지막 두 요청은 공식 지침·USER 내용이 실제로 연결돼 있을 때 가능하다. 파일이 아직
읽히지 않았거나 현재 버전이 아니면 그 상태를 먼저 설명한다. 시험 범위가 미확정이면
확정 범위의 시험 대비처럼 표현하지 않는다.

## 9. 입력 UX에서 요구하지 않을 것

- 교수 파일명을 내부 ID 규칙으로 일일이 바꾸기.
- 강의자료를 수업 수만큼 복사하기.
- 전사문을 미리 요약하거나 인식 오류를 전부 고치기.
- 교과서 파일을 모든 수업에 다시 업로드하기.
- 매 파일의 Drive ID나 Notion 관계를 설정 파일에 직접 적기.
- 파생 파일을 손으로 편집하거나 학습용 원문과 섞어서 다시 업로드하기.

반대로 과목, 자료 역할, 실제 강의 날짜, 자료의 실제 사용 범위처럼 잘못 추정하면
학습 맥락이 달라지는 정보는 필요한 시점에 명확히 확인한다.

## 10. 내부 구현과 연결할 때 지킬 경계

- 입력은 worker의 쓰기 경로이고, MCP 검색 표면은 read-only로 유지한다.
  ‘자료 추가’ 버튼 때문에 검색 MCP에 업로드·승인 권한을 합치지 않는다.
- 학기 단일 업로드함은 과목 미지정 접수 계층으로 둔다. 확정된 과목 연결 또는 등록된
  과목별 folder ID → Course identity로 정식 수집에 전달한다. 표시 이름·AI 추측을
  정식 과목 identity로 사용하지 않는다.
- Drive 자동 정리는 검색 MCP와 분리된 쓰기 경로로 설계한다. 이동 권한과 실제 API의
  파일 ID 보존을 구현 시 검증하고, 원본 버전 이력·기존 참조·재시도 멱등성을 유지한다.
- 처리 결과와 학습 노트에는 실제 source identity/version을 연결한다. AI 노트는 SOURCE가 아니다.
- UI의 한국어 상태는 기존 처리 상태·사용 관계·학습 상태의 표시 계층이다. 새 표시 문구만으로
  frozen 상태 전이 또는 권한을 바꾸지 않는다.
- Material Usage/시험 범위 확인의 자동 적용은 명세상 HumanApprovalApplier의 정확한
  사람 승인·identity·freshness 검사를 통과해야 한다.
- 학기 접수 계층·개인 일정·기존 수업 연결·노트 작업의 저장과 실행은 UX-C1에 정의한다.
  현행 frozen과 달라지는 항목은 UX-C1 §9의 다음 버전 명세 변경 C1–C8로 명시한다.
  한 수업의 여러 전사, 다른 파일 ID로 전사 교체, 복합 실습 수집은 첫 묶음에서 자동 적용하지 않는다.
- 폴더 감지는 업로드 중인 파일이나 파생 파일을 원본으로 재수집하지 않아야 한다.
  원본 보관·버전 추적과 멱등성은 파일 추가 UX 아래에서도 유지한다.

## 11. 현재 확인한 것과 아직 구현할 것

| 항목 | 현재 상태 |
| --- | --- |
| 실제 MD 전사, 시간 구간, 정규화 Drive 파일, Notion 수업 기록 | 연결 도구를 중계해 ULS core 흐름으로 시연·readback 확인 |
| 등록된 전사 파일을 처리하는 native worker | 코드 구현. `sources.json`의 명시적 등록 필요 |
| 실제 처리 결과의 검색·후속 locator 제약 | 실제 readback snapshot으로 RetrievalEngine 검사 |
| 상시 MCP/client·분리된 provider 권한·scheduler 운영 | 이번 시연으로 완료했다고 판단하지 않음 |
| 학기 대시보드 → 과목 → 세션, 과제·학사 일정·할 일 통합 표시 | **구현할 UX**. 기존 Notion 구성과 데이터 연결 방식 확인 필요 |
| Drive 업로드함에 넣기만 하면 자동 발견·분류·이동·등록 | **미구현**. native worker는 등록 목록을 읽음 |
| PDF·교과서·실습 등 모든 형식의 native 자동 처리 | **미연결/미검증**. 현재 native source kind는 transcript만 허용 |
| 누락 정보 카드, 자료 역할 선택, 페이지 확인 UI | **구현할 UX** |
| 상세 학습 노트의 자동 생성/갱신 | **미구현**. 앞선 노트는 assistant가 직접 작성·보완 |

따라서 이 문서를 지금 실행 가능한 전체 업로드 사용 설명서로 배포하지 않는다.
현재 실제 사용은 담당자가 파일 ID·과목·날짜·대상을 등록하는 준비 절차가 필요하다.
이 수작업을 없애는 것이 다음 구현의 핵심이다.

## 12. 다음 구현의 수용 사례

첫 묶음은 실제 알고리즘 1 자료를 기준으로 **‘학기 대시보드 → 과목 → 세션’ 화면과
‘학기 + 업로드 → 과목·날짜 확인 → 정리 → 수업 기록’ 입력 경로를 연결하는 것**으로 고정한다.
UX-C1의 접수 상태·과목 매핑·참조 보존 계약을 구현하고, 전사와 강의자료 PDF로 한 수업의
학습 흐름을 완성한다. 과목별 업로드 폴더는 같은 경로의 선택 입력으로 제공한다.
다음으로 교과서·실습 역할과 원본 개정의 예외를 확장한다. 첫 대시보드의 개인 할 일·공통 일정은
USER 소유 `내 일정과 할 일`을 제공하고 기존 기록은 별도 연결 뷰로 보여준다.
공지 자동 추출 등 추가 자동화는 별도 범위다. 아래는 사용자 관점 수용 사례이고,
실행·실패·재시작 검사는 UX-C1 §8 A01–A45를 함께 적용한다. native 대시보드·연결 뷰는
직접 적용했으며, 아래 자동 접수·생성의 제품 구현과 Drive 이동은 아직 수행하지 않았다.

1. 공통 메뉴에 수업을 나열하지 않고 학기 대시보드에서 알고리즘 1의 수업 목록을 열어
   2026-03-06 세션까지 접근한다. 수업에서는 해당 과목의 수업 목록으로 돌아갈 수 있다. 과제·일정은 과목과
   대시보드에서 같은 기록을 보여주며, 학기 공통 일정에 가짜 과목을 요구하지 않는다.
2. 원래 이름의 파일을 단일 업로드함에 넣어도 접수된다. 과목이 불명확하면 선택한 파일만
   묶어서 과목을 지정하며, AI가 다른 과목으로 확정하지 않는다. 사용자에게 ID를 요구하지 않는다.
3. 과목별 업로드 폴더에 넣으면 과목 질문을 생략하고 같은 처리·학습 흐름으로 이어진다.
4. 정리 전후 Drive 파일 ID와 링크가 유지되고 원본이 덮어써지지 않는다. 실패한 이동은
   완료로 표시되지 않고 원래 위치에서 재시도할 수 있다.
5. 날짜를 모르면 필요한 정보만 묻고 업로드 날짜를 강의일로 쓰지 않는다.
6. Lecture 2 PDF와 1차시 전사문이 서로 다른 개체로 유지되고, 사용 관계는 별도로 확인한다.
7. 같은 파일 재감지로 수업·자료가 중복되지 않는다. 변경된 파일과 동일 내용의 복사본도 구별한다.
8. 한 자료를 여러 수업에 연결해도 원본을 다시 업로드하지 않는다.
9. 내 풀이와 AI 해설이 공식 문제·교수 SOURCE로 들어가지 않는다.
10. PDF 추출 불완전 또는 PC 오프라인을 ‘학습 노트 준비됨’으로 표시하지 않는다.
11. 한 수업의 준비된 원문으로, 설명·예제·증명/계산·문제/해설·근거가 있는 노트를 요청할 수 있다.
12. 노트를 생성하거나 열었다고 내 할 일·복습 상태를 자동 완료하지 않는다.

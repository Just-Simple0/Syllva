# Notion 화면과 공통 탐색 결정

작성일: 2026-09-13. UX rev10의 사용자 요청에 따른 탐색 보완.

사용자는 수업이 늘 때 공통 메뉴가 길어지는 것을 원하지 않으며, 실제 사용 장소로
Notion을 선호한다. 기존에 수용한 Notion 기본 페이지 설계를 유지하고, 합성 모형에 있던
현재 수업의 상단 바로가기를 제거한다. 이전 모형도 모든 수업을 자동 나열하는 방식은
아니었지만, 수업을 공통 메뉴에 둔 표현이 사용자 기대와 맞지 않았다.

## 고정한 동선

- 공통 탐색: 대시보드 / 현재 학기의 과목별 바로가기 / 파일 확인.
- 과목: 해당 과목의 수업 목록, 강의자료·교과서, 과제·실습, 질문·필기.
- 수업: 과목의 수업 목록에서 열고 해당 목록으로 돌아가는 링크를 제공한다.
- 대시보드의 학습 바로가기는 본문에 최대 3개로 제한한다. 현재 확인된 수업은 1개를 연결했다.
- 수업 수가 늘어도 공통 탐색 항목을 추가하지 않는다. 과목 링크는 현재 학기만 표시한다.

## Notion에서의 구성

| 보이는 구성 | Notion에서 사용하는 요소 |
| --- | --- |
| 학기 대시보드 | 학기 페이지 + 일정·할 일·과제·시험의 연결된 뷰 |
| 과목별 탭 | 현재 학기의 과목 페이지 링크 묶음; 좁은 화면에서는 줄바꿈 허용 |
| 수업 목록 | Sessions 원본의 해당 학기·과목으로 필터링한 연결된 뷰 |
| 수업 상세 | Sessions의 개별 페이지, SOURCE·AI·USER 구분, 과목 복귀 링크 |
| 파일 확인 | 파일 접수함과 관련 입력 요청으로 연결하는 페이지 |

‘탭’은 과목 간 이동을 뜻하며 맞춤 웹앱의 고정 메뉴바와 같은 모양·동작을 보장하지 않는다.
수업은 DB의 개별 기록으로 보관하며 수업마다 공통 메뉴 링크나 별도 최상위 페이지를
추가하지 않는다. Notion 자체 사이드바의 사용자가 펼친 DB·즐겨찾기까지 숨긴다는 뜻은 아니다.
최초 연결 뷰·템플릿·페이지 링크 설정과 실제 모바일 동선은 Notion에서 적용 후 확인한다.

Notion 공식 문서는 같은 원본 데이터를 여러 페이지에 보여주고 뷰마다 필터·정렬을
지정하는 구성을 지원한다. 이 요구에서는 그 기능을 사용하는 편이 별도 웹앱의 호스팅,
인증, 상태 동기화를 추가하는 것보다 관리 범위가 작다는 설계 판단이다.
파일 업로드는 Drive, 정리와 생성은 로컬 worker, 사용자의 확인과 공부는 Notion이 맡는다.

근거: [Using linked databases](https://www.notion.com/help/guides/using-linked-databases)
(2026-09-13 확인). Notion에 새 HTML 기능이 없다고 단정하거나 모든 버튼을 API로
자동 설치할 수 있다고 주장하는 결정은 아니다.

## 이번 보완의 범위와 수용 조건

`intake-prototype.html`은 가상의 입력·상태로 작동하는 동선 검토용 모형이다. Notion이나
Drive를 호출하지 않으며 실제 Notion의 스크린샷·설치 완료 화면이 아니다.
UX 정의의 탐색 문구와 모형만 보완한다. 기존 입력·승인·노트 실행 계약은 유지한다.
운영 Notion 페이지, DB 설정, Drive 정리, 제품 구현, 커밋·푸시는 이번 보완 범위에 없다.

수용 조건: 공통 메뉴에 수업이 없음; 기존/새 수업이 과목 목록에서 열림; 수업에서 과목으로
복귀 가능; 수업 상세에서는 과목 위치가 표시됨; 대시보드의 최근 수업 진입 유지; 320px와
1024px에서 새 탐색이 잘리지 않고 JS 오류가 없음. 검사는 합성 모형에 한정한다.

후속 native 적용(2026-09-13): 사용자의 직접 적용 요청에 따라 실제 학기 페이지를
내 과목 → 이어서 공부(최대3) → To DO → 캘린더 → 파일 확인 순서로 구성했다.
위 합성 모형 검토와 실제 native 저장 검증은 별개이며, 적용 범위·현재 자동화 상태는
[native 적용 기록](dashboard-native-application.md)과 [저장 결과](dashboard-native-readback.md)를 따른다.

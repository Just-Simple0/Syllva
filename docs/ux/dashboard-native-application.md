# Native Notion 학기 대시보드 적용 계획

날짜: 2026-09-13. 사용자가 화면 순서와 실제 Notion 적용을 명시적으로 요청했다.
범위: 학기 대시보드, 파일 확인 페이지, 기존 시험용 알고리즘 과목의 수업 접근 개선.
HTML 앱이나 파일 처리 backend 구현은 이번 범위가 아니다.

## 적용 내용

대시보드의 본문 섹션 순서를 아래와 같이 고정한다.
1. 내 과목: 기존 7개 과목 페이지를 그대로 연결하고 child page identity를 보존한다.
2. 이어서 공부: 최대 3개의 실제 수업 링크. 현재 확인된 수업은 1개뿐이므로 하나만
   표시한다. 이번에는 읽기 기록을 수집하는 자동화가 없으므로 자동 최근 방문 순위로
   표현하지 않고 현재 학습 바로가기라고 표시한다. 빈 예시 수업을 추가하지 않는다.
3. To DO: 기존 학기 일정 DB의 미완료 할 일·과제·유형 미지정 항목을 기한순으로 보여주는
   별도 연결 뷰. 날짜 없는 할 일도 보이고 완료 상태는 사람이 편집한다.
4. 캘린더: 같은 원본 DB의 날짜 있는 모든 유형(학사일정·과제·시험·개인 일정 등)을
   캘린더로 보여준다. 완료한 일정도 캘린더에는 남는다. 시험 날짜를 임의로 만들지 않는다.
5. 파일 확인: 실제 Drive 자료 폴더, 확인된 전사·강의자료·수업 링크와 알려진 확인 필요
   항목을 보여주는 native 페이지로 연결한다. 자동 접수 연결 전임을 짧게 표시한다.

기존 학기 ‘강의 일정’ DB를 조회한 결과 현재 기록은 0개다. 이 사용자 소유 DB를
재사용하여 중복 입력 없이 To DO/Calendar 두 뷰를 구성한다. 기존 property 이름, 기존
select/multi-select option들을 보존하고 현재 7개 과목 및 ‘할 일’·‘학사일정’ 유형만
추가한다. DB 원본을 삭제·이관하지 않고 기존 캘린더를 유지한다. 기존 UI의 과목 선택
옵션은 다른 과목들도 포함하므로 삭제하지 않는다.

option 변경 직전 원본 schema를 다시 조회한다. 각 property에서 같은 이름의 option은
기존 identity·이름·색상·설정을 그대로 재사용하고 없는 값만 추가한다. 응답 유실/실패 시
schema를 다시 읽어 실제 반영 여부를 확인한 뒤에만 재시도한다. 완료 후 기존 option의
identity와 설정이 모두 남은 superset인지 readback한다. 중간에 바뀐 schema는 최신 값에
합쳐 적용하며 이전 스냅샷으로 덮어쓰지 않는다.

이 구성은 UX-C1의 미래 worker용 `내 일정과 할 일` 모델을 배포했다고 주장하지 않는다.
이번 native UI 단계의 사용자 입력 원본은 기존 일정 DB이며 product writer/자동 이관은
연결하지 않는다. 미래 구현에서 이 기존 기록을 그대로 연결하는 매핑이 필요하다.

알고리즘 과목 페이지에는 학기 복귀 링크와 기존 Sessions 원본의 정확한 과목 Relation으로
필터링한 수업 연결 뷰를 둔다. 기존 테스트 하위 페이지, 원문, AI 학습 노트, 사용자 상태를
보존한다. 나머지 과목 본문은 이번에 재작성하지 않는다.

## 안전한 적용 및 확인

- 새 파일 확인 페이지와 To DO 연결 뷰를 만들면 즉시 반환된 ID를 작업 기록에 남긴다.
  실패 또는 응답 유실이면 부모를 다시 조회하여 중복 생성 전에 존재 여부를 확인한다.
- 부모 내용 재배치 때 기존 모든 `<page>`와 `<database url>` 블록을 유지한다.
  실제 내용은 편집 직전 다시 fetch해 변동 여부를 비교한다. 자식 삭제 허용 플래그를
  사용하지 않는다. 새 링크는 mention으로, 기존 자식만 page 태그로 보존한다.
- To DO 필터: 상태 != 완료 AND (유형=할 일 OR 유형=과제 OR 유형 비어 있음).
  캘린더: 날짜 있음. 각 뷰의 실제 반환 설정·원본 ID·순서·링크를 재조회한다.
- 조회한 원본 일정은 0개, 등록된 수업은 1개라는 사실만 사용한다. 예시 일정이나 과제,
  복습 완료 상태를 생성하지 않는다. Verified/Scope Confirmed/Recording Status를 변경하지 않는다.
- Notion MCP로 native 블록·뷰 생성과 readback을 검증한다. 브라우저 화면 접근은 승인되지
  않았으므로 픽셀 배치나 실제 모바일 렌더링 완료를 주장하지 않는다.
- 독립 웹 ChatGPT 매우 높음(사용자 승인된 Pro quota 대안)과 Gemini high로 계획·최종
  결과를 각각 검토한다. 원문 강의 내용·비공개 페이지 ID는 웹 검토에 전송하지 않는다.

수용 기준: 지정한 5개 섹션의 저장 순서, 기존 7개 과목/캘린더 identity 보존, 실제 수업
링크 1개(최대3 규칙), 편집 가능한 공유 원본 To DO와 캘린더, 파일 확인의 실제 링크와
현재 자동화 상태 표시. 실제 Notion 페이지 readback을 최종 증거로 삼는다.

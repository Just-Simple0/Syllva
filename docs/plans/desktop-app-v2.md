# Syllva v2 — 데스크탑 앱 전환 계획 (확정 방향)

상태: 계획 (2026-11-02). 프로즌 계약(v1.2)을 바꾸므로 R0에서 v2 개정서를 먼저 승인받는다.

## 1. 확정된 결정 (사용자, 2026-11-02)

| 항목 | 결정 |
|---|---|
| AI 접근 | **공식 CLI 에이전트**(구독 로그인 지원 CLI)를 앱이 서브프로세스로 구동. 구독 토큰 추출·비공식 호출 금지 |
| Notion / Drive | **제거**. 저장소는 로컬 라이브러리 + SQLite 단일화 |
| 메인 화면 | **HTML UI**. 코어가 로컬에서 서빙하고 앱 셸(웹뷰)이 표시 |
| 플랫폼 | macOS 전용 아님. **Windows 동시 지원**, **모바일은 후속으로 고려** |
| 데이터 이관 | 하지 않음. 새 라이브러리로 시작 |
| 리뷰 | 외부 이중 리뷰 파이프라인 폐지. 구현자가 단계마다 직접 리뷰하고 테스트 게이트로 검증 (§7) |

## 2. 목표 아키텍처

```
┌ 앱 셸 (웹뷰, 얇게) ────────────────────────────────────┐
│ HTML UI: 라이브러리 · 과목 · 과제 · 시험 | 우측 AI 대화 패널 │
└──────────────┬─────────────────────────────────────────┘
               │ http://127.0.0.1:<port> (세션 토큰, 로컬 전용)
       ┌───────▼─────────┐        ┌──────────────────┐
       │ uls core service │──stdio▶│ 내부 MCP (read-only) │──▶ CLI 에이전트
       │ (Python, 재사용)  │        └──────────────────┘
       └──┬───────┬──────┘
   SQLite + 파일 라이브러리   Canvas 어댑터
```

- **UI = 웹 앱.** 셸은 창·트레이·자동 시작·업데이트만 맡는다. 화면 로직이 셸에 없으므로 셸 교체(데스크탑 → 모바일 래퍼)가 쉽다. 기존 `src/uls/settings/static`(app.js 등)과 Starlette 서버가 출발점이다.
- **셸 후보:** Tauri 2(Windows·macOS·Linux, iOS/Android 지원 경로 있음) 권장. Electron은 모바일 불가. 제3자 웹뷰 임베드가 불필요해져 Tauri의 약점이 사라졌다. R2 초기에 최소 셸로 두 OS에서 서명·번들 경로를 검증한 뒤 확정한다.
- **코어:** 기존 Python 재사용. 코어는 UI·셸·OS 스케줄러에 의존하지 않는다(기존 규칙 유지).
- **MCP:** 외부 클라이언트용이 아니라 **CLI 에이전트가 ULS 컨텍스트를 받는 내부 계약**으로 유지. 검색 표면은 계속 read-only이고 capability allowlist(`get_source_chunk`)도 그대로다.
- **비밀정보:** OS 키체인(`keyring`: macOS Keychain / Windows Credential Manager). 로그·번들·프롬프트에 금지.

## 3. AI 대화 패널 (CLI 에이전트)

- 어댑터 인터페이스 `AgentAdapter`: `start(session_context) / send / stream / stop`. 초기 대상은 구독 로그인을 공식 지원하는 CLI 1~2종, 설치·로그인 상태는 앱이 감지해 안내만 하고 대신 로그인하지 않는다.
- 컨텍스트는 앱이 **허용 범위를 결정**해 MCP 도구와 시스템 프롬프트로 넘긴다. 현재 열린 과목·자료는 후보로 제시하고 사용자가 확인한다.
- 에이전트는 라이브러리를 **읽기만** 한다. 노트 저장·요약 저장은 "AI 소유" 라벨로 앱이 대신 기록한다(SOURCE 재라벨 금지).
- 에이전트에 파일시스템·셸 권한을 주는 범위는 R4에서 명시적으로 샌드박스 정책을 정한다(라이브러리 디렉터리 읽기 전용이 기본).

## 5. 기능 계획

1. **라이브러리:** 드래그 앤 드롭 → 기존 분류기(S0~S4)로 과목·종류 제안 → 한 화면 확인. 수정본 교체(버전 체인), 자연어 검색(별칭·주차·날짜·과목 이름 해석 — midterm 문제 1·4 해소).
2. **Canvas:** 기존 관측기·첨부 경로 재사용. 공지·과제·달력·공지 첨부. LTI 강의자료는 수동 업로드(숨은 API 금지 유지).
3. **요약:** 자료·주차 단위, AI 라벨 + 근거 locator 필수.
4. **과제 관리:** Canvas 과제·마감 → 목록/캘린더. 제출 상태 변경은 사람만.
5. **시험 대비:** 범위 확정(human-only) → 복습 스케줄 → 문제 생성(근거 인용 필수) → 모의고사 → 채점 → 오답 노트.

## 6. 크로스플랫폼·모바일

- **Windows:** 키체인, 경로(NFC/대소문자·긴 경로), 파일 잠금, 프로세스 종료를 R1부터 CI 매트릭스에 포함. (현재 Windows는 settings/credential 계열 195건 실패가 알려진 한계 — R1에서 정리.)
- **모바일(후속):** CLI 에이전트는 모바일에서 실행할 수 없으므로 모바일은 **데스크탑 코어에 접속하는 클라이언트**. 같은 HTML UI를 반응형으로 두고, 접속은 로컬망 페어링 또는 인증 터널만 허용한다(anyone-with-link 금지). 오프라인 독립 모바일 코어는 범위 밖.
- UI는 처음부터 반응형·터치 가능하게 설계한다.

## 7. 리뷰·품질 운영 (CLAUDE.md의 이중 리뷰 파이프라인 대체)

R0에서 CLAUDE.md의 "역할 분담/작업 파이프라인/리뷰 설정" 절을 아래로 교체한다.

1. 단계마다 계획 → 구현 → **게이트 실행**(`pytest -m contract`, `pytest -m unit`, ruff, mypy, 프로젝션 린트, 앱 스모크) → **구현자의 자체 리뷰**(diff를 불변식 표에 대조, 별도 컨텍스트의 `code-review` 패스 포함) → 커밋.
2. 자체 리뷰의 한계(자기 편향)는 **불변식 계약 테스트를 먼저 작성**하는 방식으로 보완한다. 특히 human-only 승격 불가, MCP 쓰기 부재, 소유 구분, allowlist는 릴리스 블로커 테스트로 고정한다.
3. 릴리스 후보 단계(R5 이후)에서만 외부 독립 리뷰 여부를 사용자에게 다시 묻는다.

## 9. 리스크

- 프로즌 명세 개정 범위(Notion·Drive 관련 절 다수). 삭제 위주로 제한하고 불변식은 유지한다.
- CLI 에이전트의 CLI 인터페이스·약관 변경 → 어댑터 경계를 얇게, 비대화형 출력 파싱에 의존하지 않고 가능한 한 구조화 출력을 쓴다.
- Python sidecar 번들(서명·공증, native 의존성)과 Windows 안정성 → R2 초기에 검증.
- Notion 제거로 사라지는 "사람이 직접 고칠 수 있는 화면"은 UI가 대체해야 한다. 분류 수정·삭제·복원 UX를 R2 범위에 포함한다.
- 기존 자동 분류의 Notion 요청/receipt/intent 복구 로직(수천 줄)은 저장소가 로컬로 바뀌면 대부분 단순해진다. 단순화 범위는 R1에서 모듈별로 판정한다.

# AI와 공부하기

[English](studying-with-ai.md) · [사용자 가이드](README.ko.md)

Syllva의 장점은 AI 클라이언트에 사용자가 가진 모든 자료를 한꺼번에 던지는 것이 아니라, 검색 계층이 **범위가 제한된 학업 컨텍스트**를 제공하도록 하는 데 있습니다.

## 범위가 보이는 질문하기

좋은 질문은 시스템이 대상을 안전하게 식별할 수 있을 만큼 충분한 맥락을 포함합니다.

### 개념 설명

> 운영체제 4회차의 확인된 SOURCE를 기준으로 가상 메모리를 설명해줘. 실제 주소 변환 예제 하나를 포함하고 어떤 자료 구간을 사용했는지 알려줘.

### 한 수업 복습

> 데이터베이스 2회차를 복습해줘. 정의, 예제, 내가 직접 연습할 부분을 나눠줘. 내 필기를 권위 있는 원본 SOURCE처럼 취급하지 마.

### 시험 준비

> 현재 확인된 시험 범위만 사용해서 공부 체크리스트를 만들어줘. source coverage가 불완전한 주제는 네가 내용을 채우지 말고 표시해줘.

### 주장 검증

> “X”라는 문장을 현재 과목 SOURCE 기준으로 검증해줘. 근거가 부족하거나 충돌하면 그렇게 말하고 관련 source 위치를 보여줘.

### 활동/과제 풀이 보조

> 허용된 과목 컨텍스트만 사용해서 이 활동을 풀 수 있게 도와줘. 추론 과정은 설명하되, source 사실과 내가 작성할 답은 분리해줘.

## Syllva가 연결된 답변에서 기대할 것

연결된 client는 공통 behavior contract와 서버가 강제하는 scope를 따라야 합니다. 실제 사용자 관점에서는 다음을 기대할 수 있습니다.

- source 기반 주장은 반환된 source/provenance 정보로 추적 가능해야 합니다.
- 오래되었거나 불완전한 자료를 최신의 완전한 근거처럼 조용히 사용하지 않습니다.
- 대상이 모호하면 과목/수업/자료 후보를 사용자가 선택해야 할 수 있습니다.
- AI가 만든 문장, SOURCE 원문, 사용자 소유 필기는 서로 구분되어야 합니다.
- 근거가 부족하다면 자신 있게 추측하기보다 답변 보류나 추가 자료 요청이 낫습니다.

## 후속 질문

일부 검색 흐름은 후속 접근을 위해 제한된 capability를 발급합니다. 이 capability는 범위와 현재 source 상태에 결속되며 시간이 지나거나 원본이 바뀌면 무효가 될 수 있습니다. 후속 질문이 더 이상 허용되지 않는다면 검사를 우회하려 하지 말고 client에 현재 컨텍스트를 다시 resolve/retrieve하도록 요청하세요.

## 읽기 전용 MCP로 AI가 할 수 없는 것

현재 MCP 검색 표면은 upload/approval 인터페이스가 아닙니다. client가 MCP를 통해 다음을 수행한다고 가정하면 안 됩니다.

- Drive 파일 업로드/이동;
- Notion verification 필드 생성/승인;
- 사람만 소유하는 verification/scope confirmation을 대신 체크;
- 실패한 intake 요청을 강제로 성공 상태로 변경.

지원되는 쓰기 동작은 별도의 운영자/worker 경계에서 수행합니다.

# 매일 사용하기

[English](daily-use.md) · [사용자 가이드](README.ko.md)

## 대시보드

학기 대시보드를 최상위 학습 진입점으로 사용합니다.

- **내 과목**: 현재 학기의 과목 페이지로 들어갑니다.
- **이어서 공부**: 유용한 수업 바로가기를 소수만 유지합니다. 현재 UX 정의에서는 최대 3개입니다.
- **To DO**: 미완료 할 일과 과제 성격의 항목을 봅니다.
- **캘린더**: 날짜가 있는 학사/개인 일정을 봅니다. 뷰 설정에 따라 완료 항목도 남길 수 있습니다.
- **파일 확인**: 새 자료, 접수 요청, 추가 확인이 필요한 항목을 봅니다.

## 과목과 수업

**대시보드 → 과목 → 수업** 순서로 이동합니다. 수업 기록은 Sessions 원본에 유지되고 정확한 Course relation으로 필터링합니다. 학기가 진행되어 수업 수가 늘어나도 전역 탐색이 길어지지 않게 하기 위한 구조입니다.

수업에는 원본 SOURCE 자료, AI가 만든 학습 노트, 사용자 필기가 함께 연결될 수 있지만 서로 구분되어야 합니다. AI 설명은 학습 보조물이지 원본 자료의 대체물이 아닙니다.

## 자료 추가하기

intake가 활성화된 경우 일반 사용자 흐름은 다음과 같습니다.

```text
학기 업로드 위치
    → 파일 확인 / File Intake
    → Input Request
    → 명시적 제출
    → 요청 상태 확인
```

과목, 수업/날짜, 자료 종류, 의도를 추가로 요구할 수 있습니다. 파일명에 모든 정보를 억지로 넣고 Syllva가 전부 추론할 것으로 기대하기보다 필요한 정보를 직접 보완하세요.

### 사용자가 제어하는 동작

- **제출**: 이 요청을 처리해도 된다는 의사를 명시합니다.
- **취소**: worker가 요청을 더 진행하지 않도록 합니다.

처리/status 필드는 시스템이 관리하는 projection입니다. 승인이나 성공 완료를 흉내 내기 위해 status 값을 직접 수정하지 않습니다.

## To DO와 캘린더

Notion 워크스페이스는 동일한 사용자 편집 가능 일정 원본을 To DO와 Calendar 두 뷰로 보여줄 수 있습니다. 같은 일정을 중복 입력하지 않기 위한 구조입니다.

- **To DO**: 아직 끝나지 않은 실행 항목.
- **캘린더**: 날짜가 있는 학사일정, 과제, 시험, 개인 일정.
- 과목이 있다는 이유만으로 시험 날짜를 임의 생성하지 않습니다.
- 별도 integration이 해당 필드를 명시적으로 소유하지 않는 한 완료 상태는 사용자가 관리합니다.

## 처리 중 도움이 필요한 경우

대표 상태는 다음과 같습니다.

- **Needs Input** — 누락된 과목/수업/날짜/의도 정보를 보완합니다.
- **Reconcile Required** — 외부 write/readback 결과가 불확실해 운영자 확인이 필요합니다.
- **Failed** — 재시도 전 운영자가 진단 원인을 확인해야 합니다.
- **Cancelled** — 사용자가 의도적으로 유효한 요청을 다시 제출하기 전까지 진행하지 않습니다.

사용자 관점 해결 방법은 [문제 해결](troubleshooting.ko.md), worker 명령/복구는 [운영자 가이드](../operator-guide/README.ko.md)를 참고하세요.
